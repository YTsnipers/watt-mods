# Guide for AI agents

This repository is a Claude Code plugin marketplace with one mod, **watt** (`plugins/watt`). A mod is a TypeScript hooks
module that Claude Code loads and runs in its own sandbox: it has no DOM or Node APIs and reaches everything through
the engine interface `$` (`$.state`, `$.clock`, `$.ui`, `$.fs`, ...). Read [SECURITY.md](SECURITY.md) for what the mod is
allowed to touch.

## How data flows

```
engine events ──► hooks/register.tsx (entry) ──► one register() per feature
  classic.SubagentStart/Stop, agent.list ──► agents.tsx   ──► $.state watt.agents ──► AgentRow chips
  tool.call, turn.complete, session.usage ──► register.tsx ──► $.state durations/turnStats ──► ToolUse "took 1.2s",
                                                                                              turnline.tsx numbers
  plan_progress tool calls ──► bars.tsx + plan.ts ──► $.state watt.plans (+ $.store) ──► AbovePrompt band
                                                     (track.ts terminal frames, svg.ts desktop picture)
```

Drawings read `$.state` while they render; a write to a value redraws exactly the drawings that read it. That is why the
code almost never calls `$.ui.invalidate`.

## Files

| File | Responsibility |
| --- | --- |
| `hooks/register.tsx` | Module entry: wires every feature, times tool calls, records each turn's context and usage |
| `hooks/agents.tsx` | Agent row: one chip per subagent, the 250 ms frame clock while a chip shows, end/error/decision sounds |
| `hooks/bars.tsx` | The `plan_progress` tool, its system prompt rules, the edit gate and reminders, the band above the prompt |
| `hooks/plan.ts` | Pure plan model: parsing a call into stages and steps, percent, the rules text |
| `hooks/track.ts`, `hooks/svg.ts` | How a bar is drawn: terminal Raster frames (blitted at 30 fps) and the desktop SVG |
| `hooks/raster.ts`, `hooks/tint.ts` | Cell drawing, colours with AA contrast, column widths (`columnsOf`), light/dark detection |
| `hooks/turnline.tsx` | The numbers after the turn's duration line |
| `hooks/settings.tsx`, `hooks/prefs.ts` | `/watt-settings` pane and the in-memory copy of the user's options |
| `hooks/share.ts` | Writes usage percentages to a local file for the CC Switch app |
| `types/index.d.ts` | The state contract: every `$.state` key the mod reads or writes |
| `.claude-plugin/types/` | Engine API types, generated by Claude Code (git-ignored); grep it for any `$` call or event |

## Verify a change

`tsc` needs the engine types in `plugins/watt/.claude-plugin/types/`, which are git-ignored and written only when
Claude Code loads the mod. On a fresh clone, add the repository as a marketplace and install watt first
(`/plugin marketplace add <path to this clone>`, then `/plugin install watt@watt-mods`); `validate` and `test` run
without them.

```sh
cd plugins/watt
claude plugin validate .   # what the module hooks, calls and writes; refusals
claude plugin test .       # *.test.ts(x) with the engine's test harness
npx -p typescript tsc -p . --noEmit
```

## Rules that are easy to break

- A `$.state` atom or reference must be defined in the same file that reads it; importing one makes the module fail to load.
- A `ui.render` hook never writes state. Write from a timer, an event hook or a button's `onPress`.
- A value outlives a reload of the mod. When the shape of a stored value changes, give its atom a new `shape` tag
  (see `watt.agents`, declared `Shaped<...>`).
- Widths are terminal columns: use `columnsOf` (CJK and emoji take two) and the width the surface measured
  (`e.props.columns`, `e.props.bodyColumns`, `e.viewport.columns`), never a fixed terminal size.
- Code ported from plan-progress keeps its MIT notice (`plugins/watt/NOTICE`).
- The oldest Claude Code watt runs on is `engines["claude-code"]` in `plugin.json`: a hook or `$` call that needs a
  newer build raises it there and in the Requirements section of all seven READMEs.
- `docs/index.html` is the GitHub Pages demo, built from `docs/demo/template.html` and watt's own `raster.ts`, `track.ts`
  and `plan.ts`: after changing any of them, run `docs/demo/build.sh` and commit the rebuilt page.
  `docs/screenshot.png` (in every README) is `docs/index.html#shot` captured at 2x; retake it when the drawing changes.
- Each `README.md` has translations beside it (`README.zh-TW.md`, `.zh-CN`, `.ja`, `.ko`, `.fr`, `.es`), each linking all seven on
  its third line: a change to one README is made to all seven in the same commit.
